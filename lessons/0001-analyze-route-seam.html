Lesson 0001 · Outdoor Copilot 实现

唯一分析缝：analyzeRoute

本课只教一件事：整份报告的数字，几乎都从同一个函数出来。掌握它，你就抓住了实现的脊柱。

为何从这里开始

产品要验证的是「对你的难度」是否有用，不是堆页面。Spec 把计算收敛到单一入口，方便测试与改需求时不散架——见 V0.1 Design Spec 与 README 管道图。

先建立图景

01
GPX → 点列
parseGpx 把 XML 轨迹变成 TrackPoint[]。 GPX 是轨迹交换的事实标准（ TopoGrafix / GPX）。
02
可选输入
个人档案 profile、天气 weather、计划出发 plannedStart。缺了也能算——置信度会下降。

analyzeRoute
文件：src/lib/engine/analyzeRoute.ts。输出完整 RouteAnalysis（分数、时长、挑战、建议、解释模板……）。
04
UI 只编排，不重算核心
/analyze 负责上传、档案、展示；天气与 LLM 走可选 API，失败有退路。

管道里发生了什么（够用版）

函数内部按固定顺序组合模块——你不必背公式，但要能复述顺序：

  1. 距离 / 爬升 / 中心点
  2. 分段 + 海拔剖面
  3. Base Difficulty
  4. 天气调整（含时长因子）
  5. 生理负荷参考层（学术公式；可缺省）
  6. Personal Difficulty（有档案才真正「对你」）
  7. 时长区间、挑战路段、出发建议、模板解释

生理层出处见 刘泓舟等《户外运动强度测定与定级》；在产品里它是参考层，不是主叙事。天气外部源是 Open-Meteo Forecast API，经 /api/weather 代理。

硬规则（请记住）：难度分、时长、挑战公里段只来自确定性引擎。LLM（/api/explain）最多润色中文，禁止改数字——这是信任边界，不是实现细节。

和页面的关系

Next.js 用 App Router 把文件夹映射成 URL（ 官方文档）。本产品大致是：

  • src/app/analyze/ — 交互与展示
  • src/lib/engine/ — 可在浏览器跑、也可在 Node 用 Vitest 单测
  • src/lib/history/ — 本机快照，不是云端账号

引擎测试把 analyzeRoute 当作 seam，避免 UI 改动悄悄改写难度逻辑（见 Vitest）。
