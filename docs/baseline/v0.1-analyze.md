# Baseline inventory — `v0.1-analyze`

**Tag:** `v0.1-analyze`  
**Date:** 2026-08-08  
**Purpose:** Freeze pre–Week-1 analyze MVP for later accuracy comparison.

## Product surface

| Route | Role |
|-------|------|
| `/` | Brand landing → CTA analyze |
| `/analyze` | GPX / samples → base → profile → personal report |
| `/history` | Local saved analyses |
| `/about` | How to use |
| `/api/weather` | Open-Meteo proxy |
| `/api/explain` | Optional LLM polish |
| `/api/status` | Capability probe |

## Inputs

- GPX upload (content-sniff) or built-in sample GPX
- Outdoor profile (experience, comfort distance/elevation, risk; optional physiology)
- Planned hike date / start time (weather + recommendation)

## Outputs (deterministic engine)

- Route metrics + adaptive segments + elevation profile
- Base + Personal Difficulty (0–100 + band)
- Duration range, challenges, recommendation, confidence, contributions
- Template explanation; optional LLM text (must not change numbers)

## Data (at tag time)

- Browser `localStorage`: profile, analysis history, analytics events, feedback
- No cloud user DB; Prediction not yet a first-class immutable entity

## Known limitations

- No Prediction vs Reality loop
- No Personal Model learning
- History could overwrite analysis snapshots; LLM text patching was bolted on
- Difficulty calibration frozen as baseline for Week 1+
