# 吃力程度：怎么算、怎么分档

分数表示 **这条线对「当前档案下的你」有多吃力**（0–100），不是 AllTrails 式的固定路线标签。

## 分档（`scoreBand`）

| 分数 | 档位 |
|------|------|
| 0–27 | 轻松 |
| 28–51 | 适中 |
| 52–71 | 吃力 |
| 72–87 | 很难 |
| 88–100 | 不建议 |

周末常见的北京日归线（约 8–12 km、爬升 500–800 m），对「中级 + 舒适距离 10 km / 爬升 500 m」档案，校准目标大致落在 **适中～偏吃力**，而不是一上来就「很难」。

## 计算管道

```text
GPX 点列
  → 距离 / 爬升 / 分段
  → Base Difficulty（路线本身）
  → 天气调整
  → 生理负荷微调（可缺省）
  → Personal Difficulty（对照你的舒适区）
  → 分档文案
```

### 1. Base（路线基础负荷）

用距离 `dist`（km）、爬升密度 `gain/dist`（m/km）、最长连续爬升（封顶 5 km）、陡坡占比：

- **耐力 endurance** ≈ `dist×3.4 + 密度×0.03`
- **攀爬 climbing** ≈ `密度×0.05 + 连续爬升km×9 + 陡坡占比×18`（封顶 100）
- **风险 risk** ≈ `dist×1.35 + gain/55`（很长线另加）
- **天气 weather** 中性底分约 42，再被当日天气抬升/压低
- **综合 overall** ≈ `耐力×0.36 + 攀爬×0.34 + 风险×0.16 + 天气×0.14`

旧版攀爬项系数过大（连续爬升 ×18），北京山线容易 **climbing=100**，整体被拉到「吃力/很难」。2026-08 已下调。

### 2. 天气

气温偏高、降水、雷暴、强风、高温高湿会提高 weather / risk，并拉长预估时长。失败时用中性假设（不影响能出报告）。

### 3. 生理负荷（次要）

参考刘泓舟等《户外运动强度测定与定级》估算储备心跳，对耐力/攀爬做小幅加减；缺省用人群默认，置信度较低。

### 4. 个人化

相对你的舒适距离 / 舒适爬升 / 经验 / 风险偏好加减分。  
例如爬升比舒适区多 200–300 m，会加一点攀爬分，但不会再像旧版那样猛跳。

## 为何「我觉得还好」却显示偏难？

常见原因：

1. **舒适区填低了**（默认舒适爬升 500 m）——海坨一类 700 m+ 会被标「高于舒适区」
2. **旧算法攀爬封顶**（已修）
3. **夏天湿热天气**会抬 weather，综合分上移
4. 档位是「吃力程度」不是「能不能走完」——适中/吃力仍可能是合理日归选择

想更贴你的体感：把舒适距离/爬升调到你常走的水平，或走完后回填主观难度，供后续版本校准。
